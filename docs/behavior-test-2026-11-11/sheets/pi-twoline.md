1. Pi adds your message to the active branch of the session, builds a request from the system prompt, that branch's history, the tool definitions and the model settings, and sends it through the selected provider. The provider streams back an assistant response that can contain text and tool calls; Pi records it, runs each tool call and records the results, which completes one turn. The history comes from the session tree: a session is a JSONL file of entries that each point to a parent, and the path ending at the current entry (the active branch) is converted into user, assistant and tool-result messages. Another turn starts if tool results or queued steering or follow-up messages need another model request; otherwise the run ends.

2. Codemode is a tool that lets the model write a JavaScript script which calls Pi's other tools (including MCP tools) and runs non-chat models such as classifiers and image models. The script runs in a QuickJS sandbox inside the Pi process, on the harness side, with no Node APIs, file system, network or timers and a 256 MB memory limit; it reaches the outside world only through `tools.<name>()` and `models`. Those tool calls are real, so a script that calls `tools.bash` has everything bash has, and calls made before a failure are not undone. Only the script's output (what it returns or prints, capped at 10,000 tokens by default) goes into the model's context, plus small values saved with `store()` that live in the session transcript.

3. By default the server gets `codemode` exposure: its tools are not declared to the model and are not even listed in the `codemode` tool's description. Pi turns the `codemode` tool on when the server connects and adds a short section to the system prompt naming the server, and the model writes scripts that find tools with `searchTools()`, `describeTool()` or `ALL_TOOLS` and call them as `tools.mcp__<server>__<tool>(args)`. The other options are `deferred` (declared only after `tool_search` loads a match), `direct` (declared like a built-in tool and also callable from scripts) and `hidden` (registered but unreachable). `toolExposure` can override the server's setting for individual tools or name patterns.

4. The original objection was that MCP servers dump all their tool descriptions into the context on every session (Playwright MCP was measured at 21 tools and 13.7k tokens) and do not compose, because every result has to pass through the model's context; command-line tools with a README, called through bash, avoided both. The makers said the world is not static and MCP has improved, and that Codemode solves most of the context and composition problems by letting scripts combine tool calls in a sandbox. It went into the core because the changes it needed were generally useful: the same sandbox runs non-LLM models like Jev, and an ordinary MCP extension lacked the tool-loadout metadata to mark a tool as deferred or Codemode-only. They also said the best way to influence something is to embrace it, so they want to help shape MCP for small harnesses.

5. The Pi coding agent is built to run on your machine, in a terminal, driven by one person; if the process dies you look at what happened and tell it to continue, and Earendil says that focus is not changing. Agents that run anywhere, are reachable from several surfaces, survive crashes and are steered by several people need a different shape (checkpointed tasks, pluggable storage, many concurrent conversations), and adding that would have meant straying from Pi's minimal roots. Keeping it as a separate experimental package lets them explore those designs without disrupting the coding agent. Lessons that prove themselves are meant to flow back into Pi later.

6. Mario Zechner created Pi in 2025 (he described it in a November 2025 post) after Claude Code had, in his words, turned into a spaceship with features he did not need and context he could not see. It started deliberately minimal: a very short system prompt, four tools (read, bash, edit, write), no permission prompts, and no MCP, sub-agents, plan mode, to-dos or background bash, on the rule "if I don't need it, it won't be built." Pi became the agent inside Peter Steinberger's OpenClaw, which went viral in January 2026, and Armin Ronacher became a vocal user. Earendil, founded by Ronacher and Colin Daymond Hanna, acquired the project on April 8, 2026, and Zechner joined as a major stakeholder and team member.

7. The headline reaction was strong interest: the announcement reached the top of Hacker News with roughly 1,700 points and about 600 comments, and many users praised how well the small prompt works, especially with local models. Criticisms included an uneven bar for what counts as "proven" (Jev was weeks old while MCP waited nearly two years), eroding minimalism (cache warming and a fullscreen default in a "minimal" agent, both against the 2025 design), the TypeScript/Node footprint, and doubt about the "hundreds of thousands of weekly users" claim. On the MCP reversal the makers had answered in advance in "You Said No MCP!": MCP changed, Codemode fixes the composition and context cost, and the default four-tool core is untouched unless you configure a server; fullscreen can be switched back with `tuiMode: "regular"`. I do not know of direct replies from the makers inside the thread itself.

8. Print mode cannot show the trust prompt, and with the default `defaultProjectTrust: "ask"`, no saved decision and no `--approve`, Pi skips the protected project resources: `.pi/extensions/` and `.pi/mcp.json` are not loaded (nor project settings, skills, prompts or system-prompt files). `AGENTS.md` is loaded anyway, because context files load regardless of project trust. That does not make the run safe: project trust is not a sandbox, the default tools still run with the CI user's permissions, and the `AGENTS.md`, source files and test output can all steer the model through prompt injection into running arbitrary commands. I would run Pi entirely inside a container or VM with only the files it needs, no or narrowly scoped short-lived credentials and restricted network access, pass `--no-approve` explicitly, and consider disabling context-file loading for untrusted repositories.
